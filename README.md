# 打野教练 · 决策训练场

一个用来训练《王者荣耀》打野决策能力的网页小游戏。

把一局 15 分钟的比赛压缩成 **60 个决策回合**：每回合代表 15 秒游戏时间，你从若干动作里选一个
（刷野 / Gank 上中下 / 入侵敌方野区 / 拿暴君·主宰 / 蹲草守护 / 回城补给）。
**选之前不给收益数字**，选完才结算并告诉你这一回合的最优解是什么、你亏了多少。
一局结束后给出决策复盘报告。

> 关键点：这不是考操作的游戏，是考**判断**的。它想训练的就是打野最缺的那件事——
> 在正确的时间做正确的事。

## 玩法

1. 点「开始对局」，进入第一回合。
2. 按钮上只给**局势信息**——成功率、风险提示、线权、对面打野的情报。**不显示收益数字**，你得自己判断该做什么。
3. 选完之后，引擎才告诉你它的看法：这回合的最优解是什么、你亏了多少。
4. 60 回合后出复盘报告：决策质量评分、机会成本、最亏的 5 个决策、按动作类型的决策分布、以及针对你短板的具体建议。

数字键 `1`~`7` 可直接选择对应动作。

> 为什么不显示期望收益？因为排位里没人会告诉你每个选项值多少钱。
> 事先给出数字会让人退化成「照着最大的点」，练不出真实判断力。
> 反馈放在结算之后，才是有意义的复盘。

## 地图

按王者峡谷的标准拓扑绘制（画布 1:1 逻辑坐标，1000×740）：

- **我方泉水在左下，敌方泉水在右上**
- **中路**是从左下直插右上的主对角线；**上路**沿左边上行、再沿上边右行；**下路**沿下边右行、再沿右边上行
- **河道**与中路垂直（反对角线带）——**主宰**在靠上路一侧，**暴君**在靠下路一侧
- 河道把地图切成两半：**左下是我方半场，右上是我方半场**（分别用绿/红着色，一眼能分清归属）

## 评分怎么看

| 指标 | 含义 |
| --- | --- |
| **决策质量 %** | 你的累计收益 ÷ 每回合最优解期望之和。90% 以上说明你几乎每回合都做了对的选择 |
| **机会成本** | 「完全正确决策」能多拿的金币，就是你亏掉的节奏 |
| **obj** | 拿下的中立资源数，团队贡献 |

## 七大动作与模型

| 动作 | 模型要点 |
| --- | --- |
| **刷野** | 保底收益，但机会成本可能很高。BUFF 刷了不吃就是把节奏让出去 |
| **Gank** | 成功率取决于该路**线权**、双方战力差、以及**你之前抓这条路的次数**（连抓同路会被警觉反蹲） |
| **入侵** | 收益高、风险高。核心是**情报**：只有确认对面打野在别处时才安全。连续反野有递增的时间成本，且反野后有**回撤冷却** |
| **拿暴君 / 主宰** | 团队资源。前提是「线权 + 对面打野位置明确」。对面打野失联越久，被抢概率越高 |
| **蹲草守护** | 防对面 Gank。价值随该路危险程度上升——顺风局蹲草就是浪费时间 |
| **回城补给** | 状态（health）越低，恢复收益越高。满状态回城是纯浪费 |
| **状态系统** | 持续作战掉状态，低状态会直接拉低战力（残血硬打 = 送） |

## 数值平衡怎么保证的

游戏的平衡不是拍脑袋定的，而是靠一个**无头模拟器**回归校准的：

```bash
node tools/sim.mjs 400      # 跑 400 局 × 5 种策略，输出胜率/决策质量/决策分布
node tools/check.mjs        # 自检：语法、DOM、文件完整性 + 整局渲染冒烟测试
```

`sim.mjs` 会把 `index.html` 里的内联脚本抽出来，注入最小 DOM stub 后在 `vm` 里跑，
用五种策略反复对局来验证平衡：

| 策略 | 说明 |
| --- | --- |
| `random` | 完全随机（基线：瞎打） |
| `max` | 每回合选期望收益最高（理论上限） |
| `objFirst` | 无脑优先打龙（很多中低分段的真实习惯） |
| `smart` | 接近高分段打野的判断顺序 |
| `farm` | 只会刷野的「刷子打野」 |

当前回归结果（400 局）：

```
策略      胜率    决策质量   平均经济   敌方经济   机会成本   拿龙数  Gank成功  阵亡
random      9.3%     52.1%       11990      19686      12109    6.13     10.14   14.88
max        98.5%     98.2%       17663      16856       2366    8.06      9.85    4.31
objFirst   98.8%     97.8%       17648      16949       2594    9.00      9.65    4.55
smart      90.3%     88.1%       16695      17284       4562    9.00     12.05    5.21
farm        0.3%     52.8%       12389      18529      10999    2.35      3.08    3.23
```

决策分布（`max` 策略下各动作被选中的比例）——用来确认没有哪个动作是废选项：

```
FARM 35.1% | INVADE 26.8% | GANK 21.4% | OBJ 10.9% | RECALL 5.3% | HOLD 0.4%
```

（注意回归结果每次都会有小幅浮动，这是随机模拟的正常现象。
断言检查的是**结构性关系**，比如「随机策略胜率必须显著低于最优策略」，
而不是写死某个具体数字——否则测试会因为一点噪声就误报。）

`check.mjs` 除了静态检查，还会把**整局 60 回合的界面渲染跑一遍**。
本项目交付的是一张 canvas 地图，纯静态检查看不出渲染错误（比如引用了未定义的坐标常量），
所以它会在最小 DOM stub 上逐回合真实调用渲染函数，并统计绘制调用次数：

```
✓ 整局渲染无异常
✓ 渲染覆盖了整局回合  60 回合
✓ 渲染确实产生了绘制调用  fill=2517 stroke=3621 text=2713
```

### 回归测试抓到的真实漏洞

这个模拟器在开发中抓到的问题，都记在代码注释里了：

1. **`objGold` 被重复累加**（`apply()` 里加了一次，`takeAction` 里又加一次）。
2. **打龙模型过于保守** —— 一度出现「无脑打龙」的胜率反而超过「按期望值选」，
   说明模型低估了龙的收益、高估了它的风险。
3. **反野是无限提款机** —— 对面野区永远开着，导致「一直入侵」在数学上成为最优解
   （回归测试里它占到了 51% 的回合）。修法是递增的跨半区时间成本 + 疲劳值衰减 +
   **回撤冷却**（只做前两项不够，因为疲劳每回合衰减 1，交替「反野/刷野」就能把疲劳压住）。
4. **Gank 是阈值型动作** —— 基础成功率只调高一点点，它的占比就从 3% 冲到 64%。
   最后改成「低基础成功率 + 高线权系数」，让 Gank 只在有线权时才划算，才形成真正的取舍。
5. **统计口径 bug** —— 决策分布曾按「标签首词」分组，而 `蹲草守护 上路` 这类标签没有空格，
   导致报告里永远看不到「蹲草」这一类。改成按动作类型统计。

> 改任何数值常数后，**务必重跑 `node tools/sim.mjs 400` 和 `node tools/check.mjs`**，
> 里面的断言会拦住退化。

## 本地运行

单文件网页，直接双击 `index.html` 即可，不需要构建或服务器。

## 部署

静态站点，通过 GitHub Pages 发布。仓库根目录下的 `index.html` 就是入口。
`tools/publish.mjs` 用 GitHub REST API 把文件推到仓库并开启 Pages（无需本地安装 git）。

## 目录结构

```
jungle-coach/
├── index.html          # 整个游戏（单文件：HTML + CSS + JS）
├── tools/
│   ├── sim.mjs         # 无头模拟器 / 数值平衡回归
│   ├── check.mjs       # 自检 + 整局渲染冒烟测试
│   └── publish.mjs     # 通过 GitHub API 发布到 Pages
├── README.md
└── LICENSE
```
